## LinkedIn draft

AI's water footprint is not one number. I built ThirstyAI to make that distinction explorable.

The project brings together six primary sources, India's 2025 groundwater table for all 36 states/UTs, and a decision lab that compares direct and electricity-related consumption for the same hypothetical IT workload.

The useful question is not just “how much water?” It is “which accounting boundary, which location and which alternative?” The app shows when less direct cooling water can come with more power demand. Every scenario keeps its assumptions visible.

Built with Python, SQL, browser JavaScript and an Excel audit workbook. Includes a Power BI build pack, tests and reproducible data exports. No universal water-per-prompt claim and no fabricated facility data.

Repository: https://github.com/purushotmanmooper96-bit/thirstyai

I'd value feedback on the accounting boundary, data extraction and what local evidence should come next.
